# Overview

juptune is an @nogc-first, multithreaded, highly configurable async I/O library that aims to be a batteries-included foundation for developing modern web-based applications.

Only Linux is supported right now, and I doubt that'll change anytime soon.

# Rough Feature List

Clanker free (except for some stuff in the HTTP package when I first trialed out Copilot years ago).

* All major code is `@nogc nothrow`, with some `@gc` only stuff for convenience.
  * (Most code works on preallocated buffers rather than allocating memory as needed).
* Except for cryptography primitives, all code is written in pure D.
* ASN1:
  * WIP Parser for ASN.1 notation, which powers the ASN.1 -> D compiler also provided by this project as a separate tool.
* Core:
  * Basic Data Structures: `Array`; "Immutable" `String`; `HashMap`; `SharedRefCount`.
  * A semi-typed Result struct for error handling.
  * Really bad string formatting utils that are pending a full rewrite!
* Crypto:
  * Pending a full rewrite! Wooo!
* Data:
  * Low-level zero-allocation JSON parsing and emitting.
  * High-level automatic JSON serialiser and deserialiser (includes support for `@gc` slices).
  * x509 parser, certificate store, and WIP validator.
  * Streaming base64 decoding and encoding... probably going to be rewritten at some point since it's **slow**.
  * `MemoryReader` and `MemoryWriter` for easy binary parsing & emitting.
  * PEM parser.
  * UTF8 encoding & decoding.
* DNS:
  * Very basic resolv.conf support.
  * DNS (UDP with EDNS + automatic TCP).
  * (DNS over TLS, and DNS over HTTPS should be really really easy to add, but I haven't looked into it yet).
* Event:
  * EventLoop that can support `@nogc` and `@gc` threads.
  * Each thread uses its own pool of fibers.
  * Fibers are automatically suspended upon performing using the I/O interfaces provided by this package.
  * Mutex that's integrated with the EventLoop.
  * Low-level interface for interacting with io_uring.
* HTTP:
  * Pure D TLS 1.3 client implementation.
    * (!!!Not fully production ready or secure yet!!!)
  * Low-level HTTP1 protocol interface for reading and writing.
  * Higher-level generic HTTP client.
  * A validating URI parser.
* Postgres:
  * Lowish-level driver for access to the raw Postgres protocol.
  * Higher-level client for more comfortable querying.
  * Supports _most_ of the text wire formats. Less support for the binary wire formats.
  * Only supports SCRAM-SHA-256 authentication right now.
  * Supports TLS, though with all of the caveats of Juptune's TLS implementation.

# Development

To streamline the main development workflows, a [Tiltfile](https://docs.tilt.dev/install.html) is provided (hint: `kubectl` and `ctlptl` are not actually required to install Tilt).

After installing tilt, you can simply run `tilt up && tilt down` within the root directory, and you'll benefit from the following:

* Automatic setup of the meson build directory.
* Automatic test runs on file save.
* Helper buttons and commands for various purposes (e.g. running stuff from [./devops/scripts](./devops/scripts/))

## Tooling

Required:

* meson
* ldc2 (I don't care about `dmd` and `gdc` - no guarentees they will work if you try to use them instead)

Optionally:

* act (used by Tilt to test our Github Actions)
* clang (used by some DevOps scripts)
* tilt

# AI

Back when Copilot was just a fancy autocomplete plugin in VSCode, I gave it a try since I thought it was an interesting tool to try out.

I used it mainly when working on the initial parts of the HTTP library (`v1.d` and `uri.d` in particular), however I worked under the following restrictions:

* I only ever accepted its output if it essentially ended up generating the exact code I was going to write... which wasn't too often lol.

* I let it write entire documentation comments, but only after hand writing comments for it to essentially "copy and paste" for me.

* I let it fully generate a few test cases... thoguh unfortunately I'm not able to remember which ones.

* I used it for some formatting related refactoring - the only thing I'll ever give it actual praise for being fast enough at.

Even under these conditions I was able to physically feel the effects of Cognitive Surrender, and I could actively feel my ability to reason about my own codebase dwindle.

I have since sworn off GenAI, and I'm actively hostile to any attempts to bring it into this project.

To that end I will **outright refuse PRs** from people who I don't trust as being anti-GenAI. Should I be coaxed into accepting a Clanker-ridden PR, the code will be reverted/rewritten to whatever extent possible, and the contributor of course blocked.
